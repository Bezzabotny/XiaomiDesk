# Выпуск

Первый Windows-релиз0.4.1 совместим с существующим помощником0.4; исходники Android сохранены без изменений. Уже подписанный APK можно переиспользовать: `scripts/import-helper.ps1 -Apk <путь-к-проверенному-XiaomiDesk.apk>`, затем `scripts/package.ps1`. Скрипт принимает только известный SHA-256, не обращается к ключу или паролю и не меняет подпись. Это путь подготовки текущего локального кандидата. Новая подпись нужна при изменении помощника или его пересборке для следующего релиза.

1. Проверьте VERSION, AssemblyInfo.cs и версию AndroidManifest.xml; обновите CHANGELOG.
2. Запустите `scripts/test.ps1`, сборку и ручную проверку подключения, галереи, оригиналов и экрана. Запись из встроенного окна остаётся экспериментальной до успешного испытания на обычном рабочем столе.
3. Подпишите APK постоянным приватным ключом: `source/build-android.ps1 -Release -SigningKey <путь-вне-репозитория> -Jdk <JDK> -BuildTools <build-tools> -AndroidJar <android.jar>`. Пароль передаётся через `XIAOMIDESK_SIGNING_PASSWORD`; не вставляйте его в командную строку или файлы проекта.
4. Запустите `scripts/package.ps1`, проверьте архив и SHA-256. Исходники публикуются в Git; Windows-архив прикладывается к Release.
5. Создайте **draft prerelease**, проверьте содержимое и описание, затем опубликуйте из GitHub.

Workflow `release.yml` запускается вручную и создаёт только черновик. В secrets репозитория нужны `ANDROID_KEYSTORE_BASE64` (содержимое постоянного .p12 в base64) и `ANDROID_KEYSTORE_PASSWORD`. Alias ключа — `xiaomidesk`. Используйте тот же ключ для всех обновлений; потеря ключа не позволит обновлять установленное приложение без переустановки. Ключ не попадает в архив.

Workflow CI не получает release-секреты и не публикует релизы. Сборки CI подписаны ключом разработки и служат только проверке сборки.
